# Canvas RAG Solver

문제 위에 커서를 두고 `⌘⇧Y`를 누르면 선택 문항을 캡처하고, 선택한 AI 모드로 풀이한 뒤 Mac 메뉴 막대에 보기 번호를 표시하는 개인용 초안입니다. 외부 제품 패키지나 자체 서버가 없습니다.

## 풀이 모드 (2026-10-20 추가)

메뉴 막대 → **설정 → 풀이 모드 → 저장**에서 선택합니다. 기존 설치의 기본값은 RAG로 유지됩니다.

| 모드 | 동작 |
| --- | --- |
| 일반 AI | 자료 등록 없이 문항 이미지·텍스트와 AI 지식으로 판단합니다. 등록 파일을 풀이 요청에 보내지 않습니다. |
| 첨부자료 우선 AI | 자료 관리에서 **첨부**를 체크한 원본 파일을 먼저 참고합니다. 자료에 답이 없거나 부족하면 AI 지식으로 판단합니다. 체크한 파일이 없어도 작동합니다. |
| RAG · 자료 근거만 | 준비된 자료를 검색하고, 검색 구절에 근거가 없으면 답을 보류합니다. |

**첨부 사용법:** 자료 관리 → 자료 추가(PDF/TXT/MD) → 사용할 파일의 **첨부** 체크. 새 파일은 자동 체크되며, 이전에 등록한 파일은 직접 체크합니다. 인덱싱 중인 파일도 직접 첨부할 수 있습니다. 일반 AI는 체크와 무관하게 자료를 사용하지 않고, RAG는 준비된 자료 전체를 검색합니다. 모드나 사용 파일 변경은 진행 중 요청과 최근 답을 지웁니다.

원본 첨부는 파일당 **50 MB 미만, 합계 50 MB 이하**입니다. PDF는 텍스트와 페이지 이미지를, TXT/MD는 텍스트를 입력하므로 요청마다 입력 토큰과 비용이 커질 수 있습니다. 모델 문맥 한도를 넘거나 파일/API 오류가 나면 오류를 표시합니다. 파일을 몰래 제외하거나 일반 AI로 자동 재시도하지 않습니다. 자료 등록은 기존 RAG 인덱싱도 수행하므로 저장 비용도 고려하세요. ([OpenAI File inputs](https://developers.openai.com/api/docs/guides/file-inputs))

업로드 중에는 원본 파일을 수정·교체하지 마세요. 현재 업로드 후 로컬 파일 크기를 기록하므로, 변경하면 서버 파일과 크기가 달라져 첨부 용량 검사가 어긋날 수 있습니다.

최근 결과와 아이콘 툴팁에 **자료 기반 / AI 지식으로 판단 / 자료 + AI 지식**을 표시합니다. RAG 인용은 검색 구절과 대조하지만, 원본 첨부 인용은 파일 ID만 검증하며 **원문 확인 필요**로 표시합니다. 자료 부족 여부와 근거 구분은 모델의 자기 보고이므로 오판할 수 있습니다. 일반 AI에는 웹 검색·외부 에이전트 도구를 연결하지 않았습니다.

업데이트는 메뉴 앱을 **종료**한 뒤 Aside 확장 → **메뉴 앱 연결** → `—` 메뉴 → **사용 시작**으로 적용합니다. 확장은 변경하지 않아 다시 로드할 필요가 없습니다. 모드별 모의 API 검사는 통과했으며 실제 유료 호출·원본 파일별 인식 품질은 미검증입니다.

**현재 상태:** 앱·확장 소스, 로컬 검사, 실제 Aside의 Native Messaging 연결을 확인했습니다. 확장 ID `ampldoldkpkhjiaaeolcpbjnlobgnpan`의 host를 설치했고 `canvas.skku.edu` origin과 `⌘⇧Y`를 등록했습니다. 첫 실행은 캡처 미리보기로 대기 중입니다. 실제 API 자료와 과목별 품질 평가는 아직 하지 않았습니다.

## Caps Lock LED 알림 (2026-10-20 추가)

MacBook 내장 키보드의 Caps Lock LED로 답 번호를 알립니다. 메뉴 막대 → **설정 → 정답 번호만큼 Caps Lock LED 깜빡이기 → 저장**에서 켭니다. 기본값은 꺼짐이며 일반 AI·첨부·RAG 모두 적용됩니다. 메뉴 번호는 그대로 유지합니다.

- 정답 3번이면 3회, 한 문항당 한 번 점멸합니다. 원래 LED가 꺼져 있으면 켜졌다 꺼지고, 켜져 있으면 꺼졌다 켜지는 것을 한 번으로 셉니다. 반전 250ms / 원래 상태 350ms 간격입니다.
- 새 문항·취소·중지·설정 또는 사용 자료 변경·정상 종료는 점멸을 취소하고 원복합니다. 이전 점멸 원복이 끝난 뒤 새 점멸을 시작합니다.
- HID LED 출력만 조작합니다. 키 이벤트를 보내거나 Caps Lock 입력 상태·한영 입력 소스를 변경하지 않으며 키 입력을 수집하지 않습니다. 사용자가 그 사이 Caps Lock 상태를 바꿨다면 원복은 현재 상태를 따릅니다.
- **LED 3회 테스트**는 키·자료·AI 호출 없이 동작합니다. 처음 켜거나 테스트하면 macOS 입력 모니터링 권한 요청이 나올 수 있습니다. **시스템 설정 → 개인정보 보호 및 보안 → 입력 모니터링**에서 요청에 표시된 실행 앱(Aside 또는 Canvas RAG Solver)을 허용하고 메뉴 앱을 재연결한 뒤 다시 테스트하세요.
- LED 접근 오류는 설정의 상태 안내·최근 결과·툴팁에 표시하며 AI 답 번호를 지우지 않습니다. 외장·가상 키보드는 점멸 대상에 포함하지 않습니다. 강제 종료·전원 차단 때는 원복을 보장하지 못합니다.
- 원복에 실패하면 오류를 유지하고 해당 앱 세션의 추가 점멸(테스트 포함)을 중단합니다. 표시등 상태를 확인한 뒤 메뉴 앱을 재연결하세요.

이 Mac의 초기 읽기 검사에서는 내장 키보드를 찾았으나 HID 접근이 NotPermitted였습니다. 이후 사용자가 앱의 **3회 테스트가 실제로 동작함**을 확인했습니다. 모든 답 번호의 실제 점멸·이미 켜진 LED·점멸 중 키 조작·종료의 하드웨어 조합은 아직 모두 검수하지 않았습니다. ([Apple LED 출력 API](https://developer.apple.com/documentation/iokit/1588651-iohiddevicesetvalue))

테스트가 되다가 **재빌드 후 `내장 LED 접근 실패 (-536870174)`**가 발생하면 입력 모니터링 권한을 다시 등록하세요. 현재 `build.sh`는 임시(ad-hoc) 서명을 사용하며, 이 서명은 특정 빌드의 실행 파일 해시에 묶입니다. 같은 앱 이름·경로여도 다음 빌드가 기존 권한을 이어받지 못할 수 있습니다. ([Apple 서명 요구사항 설명](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements))

1. 메뉴 앱을 종료합니다.
2. 시스템 설정 → 개인정보 보호 및 보안 → 입력 모니터링에서 기존 **Canvas RAG Solver** 항목을 제거합니다.
3. ‘+’로 `/path/to/ai-solver/build/Canvas RAG Solver.app`을 다시 추가하고 허용합니다.
4. Aside 확장 → 메뉴 앱 연결 → 설정 → LED 3회 테스트로 확인합니다.

복구 확인 중에는 앱을 다시 빌드하거나 재서명하지 마세요. 업데이트 간 권한을 안정적으로 유지하려면 고정된 코드 서명 인증서가 필요하며, 현재 빌드는 그 구성이 아닙니다.

## 설치

필요 도구는 Xcode Command Line Tools의 Swift, Node, Python3입니다. 빌드는 현재 Mac 아키텍처를 사용하며 deployment target은 macOS13입니다. 오래된 macOS에서의 실행은 별도 검증 전입니다.

```sh
cd /path/to/ai-solver
bash scripts/check.sh
bash scripts/build.sh
```

1. Aside의 `chrome://extensions`에서 개발자 모드를 켭니다. **압축해제된 확장 프로그램 로드**로 이 저장소의 `extension` 폴더를 선택합니다.
2. 표시되는32자리 확장 ID로 Native Messaging host를 등록합니다. 아래 `확장ID`를 실제 ID로 바꿉니다.

```sh
bash scripts/install.sh 확장ID "$HOME/Library/Application Support/Aside/NativeMessagingHosts"
```

위 Aside 경로는 실제 `chrome://version`의 프로필 `…/Aside/Default`에서 확인한 user data root를 기준으로 하며, 이 경로에서의 실제 연결도 성공했습니다. 다른 브라우저에서는 그 브라우저의 user data root 아래 `NativeMessagingHosts`를 지정하세요. 경로 규칙과 프로토콜은 [Chrome 공식 문서](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging)를 따릅니다.

3. **확장 메뉴 → 메뉴 앱 연결**을 누릅니다. 메뉴 막대에 `—`가 나타납니다. 새 연결은 사용 중지로 시작합니다. 이 앱은 확장 포트로 시작하므로 Finder에서 직접 실행하지 않습니다.
4. Mac 메뉴의 **설정**에서 API 키를 저장합니다. 키는 Keychain에만 저장합니다. 기본 모델 ID는 `gpt-4.1-mini`이며 이미지·구조화 출력을 지원하는 모델로 변경할 수 있습니다.
5. 설정에서 **풀이 모드**를 선택합니다. 일반 AI는 자료가 필요 없습니다. 첨부자료 우선 AI는 자료 관리에서 PDF/TXT/MD를 추가하고 **첨부**를 체크합니다. RAG는 파일별 `준비됨`을 확인합니다. 스캔·수식·그림의 인식·검색 품질은 실제 자료에서 별도로 평가해야 합니다.
6. 실제 `canvas.skku.edu` 문항 탭에서 확장 메뉴의 **현재 사이트에서 사용**을 누릅니다. 팝업에 등록된 origin과 단축키가 표시됩니다. 단축키가 비었으면 `chrome://extensions/shortcuts`에서 지정합니다.
7. Mac 메뉴에서 **사용 시작**을 선택합니다. 먼저 확장의 **다음 단축키로 캡처만 미리보기**를 누르고 팝업을 닫습니다. 문항 번호 위에 커서를 두고 `⌘⇧Y`를 누릅니다. 본문·모든 보기·그림과 이웃 문항 혼입 여부를 확인합니다. 이 모드에서는 API를 호출하지 않습니다. 캡처 검사만 할 때는 키와 자료 등록 전에도 사용 시작이 가능합니다.
8. 그다음 단축키부터 선택 모드로 풀이를 실행합니다. 최근 결과에서 원래 보기 라벨·판단 근거 구분·파일명·모델 사용량을 볼 수 있습니다.

앱 종료 후에는 확장 메뉴에서 다시 연결하세요. 포트가 끊기면 앱과 작업이 종료되며, 이전 요청을 자동 재전송하지 않습니다. 저장소를 이동하거나 확장을 다시 로드해 ID가 바뀌면 등록 명령을 다시 실행하세요. 빌드 후에는 실행 중인 앱을 종료하고 다시 연결해야 새 실행 파일을 사용합니다.

## 동작과 데이터

`단축키 → 고정된 DOM 스냅샷 → 탭 캡처 → 확장 안에서 crop → native 앱 → 선택 모드(일반/첨부/RAG) → Responses 풀이 → 메뉴 번호`

- 한 번에2~10개 보기의 단일 문항만 처리합니다. 메뉴의 숫자는 보기 순서의1-based 값입니다.
- 여러 문항이 보여도 선택 문항 하나의 본문·보기만 전달합니다. 화면 밖 문항을 자동 스크롤하거나 합성하지 않습니다.
- 캡처 전후에 탭·문항 내용·좌표·스크롤·크기를 확인합니다. 선택한 뒤 커서만 움직이면 처음 선택한 문항을 유지합니다.
- 새 단축키, 문서·화면·자료 변경, 중지, 연결 종료는 진행 중 작업과 최근 결과를 지웁니다. 늦게 도착한 성공·오류는 무시합니다. 전체 제한은45초이며 자동 재시도하지 않습니다.
- `…` 처리 중, `?` 보류·지원 밖, `!` 오류, `—` 중지, `·` 대기입니다. 숫자는 보기 범위·원래 라벨·모드별 근거 형식을 검사한 결과에만 표시합니다. RAG는 검색 파일 ID·인용문을 대조하고, 첨부는 선택 파일 ID를 확인합니다. 어느 모드도 정답 자체를 보장하지 않습니다.
- 전체 탭 이미지는 확장 메모리에서 자릅니다. 외부에는 **선택 문항 PNG·텍스트와 등록 자료**가 전송됩니다. 이미지·문제·키를 로그나 디스크에 저장하지 않습니다. 개발용 미리보기는 메모리에서 만료됩니다.
- Responses의 `store:false`를 사용합니다. 등록 자료는 별도로 OpenAI 서버에 저장됩니다. 제거는 Vector Store 연결과 Files 객체를 모두 삭제하며 일부 실패는 `삭제 실패`로 남아 재시도할 수 있습니다.
- native 입력16MiB, PNG10MiB·40M pixels·한 변20000px, 문제 텍스트64KiB 한도를 둡니다.

## 검증

```sh
bash scripts/check.sh         # JS 구문, 확장 흐름, 설치기, native/API 모의 응답

node scripts/browser-check.cjs # 별도 임시 Chrome 프로필: DOM·실제 PNG crop
python3 scripts/native-smoke.py # 임시 앱: 실제 stdio·origin·취소·EOF
```

브라우저 검사에는 설치된 Google Chrome을 사용하며 `TEST_CHROME`으로 실행 파일을 지정할 수 있습니다. 사용자 Chrome/Aside 프로필을 복사하거나 사용하지 않습니다. API 검사는 URLProtocol 모의 응답만 사용합니다. 실제 API 키·자료 업로드·유료 호출은 실행하지 않았습니다.

| Native/API/LED self-check |63개 통과: 기존 47개 + LED 설정 이행·횟수·간격·켜짐/꺼짐 원복·취소·오류·교체 순서·중복 방지·잠금 상태 변화·원복 실패 후 차단 16개 |
| 편집 단축키 |2개 통과: 실제 AppKit 메뉴에서 ⌘V·⌘A 명령 전달. 시스템 클립보드는 읽거나 변경하지 않음 |
| 확장 workflow |5개 통과: crop만 전송, 탐지 실패·이전 답 취소, 캡처 중 탭 전환, stale 상태 무시, 실제 단축키 표시 |
| 설치기 |2개 통과: 단일 origin·재등록·다른 host 보호, 잘못된 입력 거절 |

PNG 배율 검사는 실제 이미지 픽셀 검사입니다. 실제 Aside 브라우저 줌80/100/125/150%와 Retina 캡처 검수 전체를 대신하지 않습니다. 실제 화면의 다중 문항 캡처, 서비스 워커 강제 재시작·재연결, Keychain·자료 관리 UI 조작, 실제 자료의 검색 정확도, 정답20문항의 정확도·지연·비용은 아직 미검증입니다. 네이티브 UI 자동화 도구가 timeout되어 설정·자료 창의 실제 조작 검수는 사용자 확인이 필요합니다.

클립보드 감시, 자동 정답 선택·제출, 범용 OCR, 여러 브라우저 동시 운용은 넣지 않았습니다.

설정 입력창에서 `⌘V`가 동작하지 않던 문제는 표준 편집 메뉴 누락을 수정했습니다. 수정 빌드를 적용하려면 실행 중인 메뉴 앱을 종료한 뒤 확장 메뉴의 **메뉴 앱 연결**로 다시 실행하세요.
